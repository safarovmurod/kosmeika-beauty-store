# Каталог косметики — рабочий прототип

React + TypeScript + Vite, Fastify + TypeScript, PostgreSQL + Prisma. «Lumière» — временное название, изменяется в настройках. Телефон WhatsApp: +992 90 648 00 08. Настоящие названия, цены, остатки, оттенки и описания товаров владельцем пока не предоставлены.

**Статус:** frontend опубликован на Vercel; серверный вариант подготовлен для Vercel Functions и VPS. Локальные интеграционные проверки на настоящем временном PostgreSQL покрывают миграции, вход владельца, запрет посторонних аккаунтов, защищённые запросы, фотографии, сохранение после пересоздания приложения, logout и дедупликацию событий. Отдельно требуется проверить подключение production-базы и живой deployment, задать пароль владельца приватно и проверить восстановление резервной копии.

## Что находится в проекте

- `client/` — витрина и отдельно загружаемая админ-панель.
- `server/` — API, сессии, обработка фото, события и серверные команды.
- `shared/` — общая схема проверки данных.
- `prisma/` — схема и начальная миграция PostgreSQL.
- `assets-source/products/` — 28 исходных фотографий из предоставленного архива; оптимизированные копии лежат в `public/images/products/`. `hero.webp` — сгенерированное декоративное изображение.
- `uploads/` — создаётся сервером, должен размещаться на постоянном диске и не попадает в Git.

Цены сохраняются целыми числами в дирам (1 сомони = 100 дирам). Каталог на пустой базе пуст. Неизвестные данные не подменяются реальными. Отдельная команда ниже добавляет демонстрационные карточки с предоставленными фотографиями: они помечены как демонстрационные, без цены и без возможности заказа.

## Локальный запуск

Нужны Node.js 24 LTS, npm и Docker с Compose. Команды выполняются из папки проекта. В PowerShell:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` приватно и заполните:

```text
POSTGRES_PASSWORD=<придумайте уникальный пароль базы>
DATABASE_URL=postgresql://beauty:<пароль_базы>@localhost:5432/beauty
PUBLIC_ORIGIN=http://localhost:5173
PORT=3000
UPLOAD_DIR=./uploads
```

Значение пароля базы в URL должно быть URL-encoded, если содержит специальные символы. `.env` нельзя коммитить или отправлять другим людям. `PUBLIC_ORIGIN` должен точно совпадать с адресом, открытым в браузере, включая порт. Затем:

```powershell
npm ci
docker compose up -d db
npm run db:migrate
npm run admin:create
npm run db:seed
npm run dev
```

`admin:create` интерактивно попросит дважды ввести новый пароль, не отображая его. Логин владельца: `safarovmancho@gmail.com`. Команда откажется перезаписывать существующую учётную запись. `db:seed` необязательна и откажется добавлять примеры в непустой каталог. Откройте `http://localhost:5173`, панель — `/admin`.

В Windows можно дважды щёлкнуть `create-admin.cmd` в папке проекта: он запускает ту же команду. Сначала должен быть настроен локальный игнорируемый `.env` с нужной базой. Введите новый пароль два раза в открывшемся окне — символы не отображаются. Пароль не нужно вводить в чат или настройки frontend.

Для замены забытого пароля на сервере с доступом к базе выполните `npm run admin:create -- --reset`. Команда интерактивная, меняет хеш и отзывает все сессии. Публичного endpoint восстановления нет. Не вводите пароль в аргумент командной строки и не пересылайте его в чат.

## Сборка и запуск на сервере

```bash
npm ci
npm run db:migrate
npm run build
NODE_ENV=production npm start
```

Нужны постоянный PostgreSQL, постоянная папка `UPLOAD_DIR` вне каталога приложения, домен и HTTPS reverse proxy. В production укажите `PUBLIC_ORIGIN=https://ваш-домен` без завершающего слеша, рабочий `DATABASE_URL`, абсолютный `UPLOAD_DIR`, `PORT` и `NODE_ENV=production`. Приложение слушает `127.0.0.1` по умолчанию; proxy должен направлять на этот порт все запросы, включая `/api` и `/uploads`. `HOST` меняйте только при необходимости. Приложение не доверяет forwarded IP-заголовкам (`trustProxy: false`), поэтому за proxy ограничитель частоты может считать все запросы пришедшими с одного IP. До публичного запуска настройте проверенную инфраструктуру и лимитирование на proxy; не включайте доверие всем прокси вслепую.

Настройте DNS домена и HTTPS-сертификат на выбранном сервере. После публикации откройте прямую ссылку на изображение `/uploads/...` с другого устройства по HTTPS и проверьте её доступность без авторизации. `wa.me` передаёт ссылку на фотографию текстом; файл не прикрепляется автоматически, превью не гарантируется. GitHub Pages не предоставляет нужные сервер, PostgreSQL и постоянное хранилище.

## Бэкап и восстановление

Храните резервные копии базы и папки загрузок вместе, отдельно от сервера, с ограниченным доступом. Пример для Docker Compose в Linux shell; сначала остановите изменение данных в панели, чтобы копии соответствовали друг другу:

```bash
docker compose exec -T db pg_dump -U beauty -d beauty -Fc > beauty-db.dump
tar -czf beauty-uploads.tar.gz -C /путь/к/родительской/папке uploads
```

Для восстановления используйте новую пустую тестовую базу того же основного PostgreSQL и отдельную пустую папку; не перезаписывайте рабочие данные без отдельной проверки. Пример:

```bash
docker compose exec -T db pg_restore -U beauty -d beauty --clean --if-exists < beauty-db.dump
tar -xzf beauty-uploads.tar.gz -C /путь/к/родительской/папке
```

После восстановления проверьте товары, изображения, вход и `/api/health`. Регулярно делайте пробное восстановление. Эти команды подготовлены, но восстановление в текущей среде не проверено.

## События и ограничения

`view` — загрузка витрины, `product` — открытие товара с выбранным вариантом, `whatsapp` — клик по ссылке заказа. Это события, а не люди или продажи. ID событий не позволяет повторно записать то же событие; авторизованные администраторы и простые user-agent ботов исключаются по возможности. Статистика ограничена 100 000 событиями за запрос; при большем количестве нужен серверный агрегатор. Доля визитов с кликом и уникальные посетители не рассчитываются: идентификатора визита здесь нет. Полные IP не сохраняются в таблице событий; проверьте политику хранения обычных серверных и proxy-логов. Для удаления событий старше 180 дней (или `EVENT_RETENTION_DAYS`):

```bash
npm run events:cleanup
```

Эту команду нужно запланировать системным планировщиком самостоятельно. Файлы, больше не используемые товарами, автоматически не удаляются: безопасная сверка ссылок перед ручной уборкой обязательна.

## Проверка и известные незавершённые части

`npm run typecheck`, `npm run lint`, `npm run build`. Для сборки `DATABASE_URL` не нужен. Для миграций и работы сервера требуется настоящее подключение к PostgreSQL.

### Vercel

Vercel собирает Vite frontend и функцию `api/server.mjs`, которая обслуживает Fastify API, фотографии и серверные метаданные товаров с одного origin. Необходимо подключить постоянную PostgreSQL (например Neon Free) и добавить `DATABASE_URL` (pooled) и `DATABASE_URL_UNPOOLED` (direct) в Environment Variables проекта для **Production**. Prisma Migrate использует direct URL; приложение использует pooled URL. Для обычного локального PostgreSQL достаточно одного `DATABASE_URL`. Укажите `PUBLIC_ORIGIN=https://kosmeika-beauty-store.vercel.app`; логин администратора выполняйте на этом основном домене. Для preview используйте отдельную тестовую базу и соответствующий origin — production-базу к preview не подключать.

Vercel использует `npm run build:vercel`: сначала применяет миграции, затем выполняет строгую проверку типов и сборку. При отсутствующей или неработающей базе deployment должен завершиться ошибкой. Node.js закреплён на 24.x. Секреты не должны иметь префикс `VITE_`.

Диск Vercel Functions не постоянный. Поэтому на Vercel новые фотографии и миниатюры хранятся в таблице `Image` PostgreSQL как WebP и выдаются по прежним `/uploads/<UUID>.webp`; резервная копия базы включает эти фотографии. Предел входного файла на Vercel — 4 МиБ, ниже лимита payload платформы. Это решение рассчитано на небольшой каталог; контролируйте общий размер базы и лимиты бесплатного плана. Исходные 28 фотографий из архива остаются статическими файлами проекта. На VPS загрузки сохраняются в постоянном `UPLOAD_DIR`, как раньше.

После подключения production-базы сохраните её URL только в локальном игнорируемом `.env`, выполните `npm run db:migrate`, затем `npm run admin:create` в своём терминале. Пароль вводится скрыто, только владелец его знает; команда не создаёт пароль по умолчанию. Восстановление: `npm run admin:create -- --reset`, с отзывом всех сессий. Вход разрешён только email из `server/owner.ts`. Создание покупательских аккаунтов отсутствует. Повторные попытки входа ограничиваются и в PostgreSQL, поэтому пересоздание Vercel Function не сбрасывает лимит. Просроченные окна и сессии очищает `npm run events:cleanup`.

Проверки: `npm test` поднимает изолированный временный PostgreSQL, не использует production-базу и останавливает его после тестов. Временные файлы `.test-postgres/` игнорируются Git. На Windows запуск тестов требует разрешения локальных процессов PostgreSQL; системный сервис и новые пользователи ОС не создаются.

Не завершены: полные браузерные e2e-тесты; проверка production-базы на нескольких устройствах; публичные HTTPS-ссылки; нагрузочные и мобильные performance-измерения; безопасная автоматическая очистка неиспользуемых файлов; настоящая конверсия визитов; связанные товары; кнопки изменения порядка товаров (доступно числовое поле); отдельное редактирование и сортировка категорий; полноценная локализация; проверка предпросмотра ссылок в социальных сетях. Форматы изображений проверяются через Sharp; интеграционные тесты проверяют запрещённый SVG и превышение лимита. Не считать этот список результатом независимого аудита безопасности.
